## Executive Summary

1. **Taxonomy Design Verdict:** Encoding **execution lifecycle, host dependency, speed, and isolation profile** inside `[Category]`—orthogonal to feature modules already targeted via VSTest `FullyQualifiedName~Modules.<Slice>`—aligns directly with Microsoft VSTest, NUnit, `Nice3point/RevitUnit`, `DynamoDS`, and `speckle-sharp-connectors`. `Synthetic`'s proposed 5-category taxonomy (**`Unit`**, **`Architecture`**, **`RevitSmoke`**, **`RevitAdapter`**, **`RevitIsolatedDoc`**) is **architecturally sound** and should be adopted with clear seam contracts and typed custom `CategoryAttribute` subclasses (plus an optional temporary `Quarantine` tag for known upstream Revit bugs).
2. **Critical Runner Finding (`ricaun.RevitTest` `1.11.1`):** Direct reflection and metadata inspection of `ricaun.RevitTest.TestAdapter` (`1.11.1`) and its embedded `ricaun.NUnit` (`1.5.0`) engine proves that `ricaun.RevitTest.TestAdapter`'s `TestFilter` **only supports `FullyQualifiedName` and `Name`** (`SupportedPropertiesCache` contains zero `TestCategory` or `Category` keys), and `ricaun.NUnit` (`1.5.0`) **does not inspect `CategoryAttribute`** during discovery or execution. Therefore, `--filter "TestCategory=Unit"` and `--filter "TestCategory=Architecture"` work today in [SyntheticTests.Logic.csproj](../../tests/SyntheticTests.Logic/SyntheticTests.Logic.csproj) (`NUnit3TestAdapter`), **but `--filter "TestCategory=RevitSmoke"` does not work out of the box in `SyntheticTests2023–2026`** without also encoding the tier in the fixture namespace/class name (for `FullyQualifiedName~` filtering) or extending the adapter/runner.
3. **Additional Test Types Verdict:**
   - **Adopt (Fold into `Unit` & `RevitAdapter`):** Golden-file / round-trip contract verification (`Verify.NUnit` or deterministic JSON/OpenXML assertions for `RevitDOM`, `ExtensibleStorage` migration, and OpenXML `.xlsx` exports); Dual-tier failure-handling tests (keeping pure rule matching in `Unit` and adding real Revit transaction failure triggers in `RevitAdapter`); Selective property-based testing (`CsCheck`) in `Unit` for 3D transforms, solar math, and 5-step **Identity Comparison** invariants.
   - **Adopt as Split-Seam Practice (Fold into `Unit` + `RevitSmoke`):** Headless STA WPF layout/theme/binding tests in `Unit` (continuing [ThemeTests.cs](../../tests/SyntheticTests.Logic/Infrastructure/UI/ThemeTests.cs)), paired with minimal in-Revit `Window.Show()` / `ExternalEvent` wiring checks in `RevitSmoke`.
   - **Adopt as Harness / Compilation Invariants (Not New Categories):** Multi-version `RevitAPI` compilation/execution across `net48` / `net8.0` / `net10.0` plus post-run **Revit Journal** (`DBG_WARN`, orphaned transactions) and open-document leak assertions in [test_executor.py](../../.agents/skills/revit-tests/scripts/test_executor.py) and `[OneTimeTearDown]`.
   - **Fold into `RevitIsolatedDoc`:** Background `EditFamily` / `LoadFamily` cycles, linked-model positioning, `SaveAs`, and detached workshared tests.
   - **Skip:** External UI automation (`FlaUI` / `WinAppDriver`) due to desktop-focus contention, WPF dispatcher timing flakiness, and high leverage already achieved through MVVM + `Fake<Slice>Adapter` + STA layout checks.

### 1.2 Key Primary-Source Takeaways

1. **Test runner separation matches host seams, not business features.** Neither `DynamoDS` nor `speckle-sharp-connectors` nor `Nice3point` proliferates test categories for every BIM feature. Instead, `Nice3point/RevitUnit` distinguishes execution context (`RevitApiTest` vs `RevitApiUiTest` with `RevitUiParallelLimit`), `Dynamo` separates pure engine (`DynamoCoreTests`) from WPF (`DynamoCoreWpfTests`) and Revit document workflows (`RevitSystemTests` + `[TestModel]`), and `speckle-sharp-connectors` separates headless converter/DUI tests from Revit-hosted integration runs.
2. **NUnit `[Category]` and VSTest `--filter` are designed to complement `FullyQualifiedName`, not duplicate it.** Microsoft Learn's selective testing specification documents that `dotnet test --filter` maps NUnit `[Category("X")]` (via `NUnit3TestAdapter`) to `TestCategory=X`, while namespace/class/method selection maps directly to `FullyQualifiedName~Substring`. NUnit documentation explicitly notes that `[Category]` applied at `[TestFixture]` level inherits to all member `[Test]`s, custom typed subclasses of `CategoryAttribute` eliminate typo drift, and `[Category]` placed on `[SetUpFixture]` is silently ignored.
3. **Binary verification of `ricaun.RevitTest.TestAdapter` (`1.11.1`) exposes an immediate filter trap.** Decompressing and inspecting `ricaun.RevitTest.TestAdapter.dll` and its embedded `ricaun.NUnit` (`1.5.0`) assembly confirms:
   - `TestFilter.SupportedPropertiesCache` registers **only** `"FullyQualifiedName"` and `"Name"`.
   - `TestFilter.get_TestCaseFilterExpression()` has zero exception-handling clauses and passes `SupportedProperties` directly to `IRunContext.GetTestCaseFilter(...)`, meaning `--filter "TestCategory=..."` is unsupported by `ricaun.RevitTest.TestAdapter 1.11.1`.
   - `ricaun.NUnit` (`1.5.0`) `TestAttributeService` inspects `[Test]`, `[TestCase]`, `[TestCaseSource]`, `[TestFixture]`, `[TestFixtureSource]`, `[OneTimeSetUp]`, `[OneTimeTearDown]`, `[Order]`, `[Ignore]`, `[Explicit]`, and setup/teardown methods—**not** `CategoryAttribute`—and `TestCaseUtils.Create(string source, string testName)` transfers only the test name string with zero `Traits`.

## 3. Taxonomy Design Principle & Critique of the 5 Categories

### 3.1 Core Principle: `[Category]` Encodes Execution Lifecycle, Not Feature Domain

In a modular codebase, two orthogonal dimensions govern how tests are selected:

1. **What code / BIM feature is under test (Feature Slice / Module):** Already encoded cleanly by folder and namespace hierarchy (`SyntheticTests.Modules.ShadowStudy.*`, `SyntheticTests.Modules.SharedCoordinates.*`, `SyntheticTests.Modules.RevitDOM.*`). Both VSTest (`--filter "FullyQualifiedName~Modules.ShadowStudy"`) and `ricaun.RevitTest` support this natively without any `[Category]` attribute.
2. **How, where, and at what cost the test executes (Execution Lifecycle / Isolation Profile):** Cannot be inferred reliably from feature names alone. A single module like `ShadowStudy` or `SharedCoordinates` needs millisecond headless tests *and* live Revit tests.

**Why mixing both axes in `[Category]` fails:** Combining feature and lifecycle (`[Category("ShadowStudy_Unit")]`, `[Category("ShadowStudy_Revit")]`) creates combinatorial category explosion, duplicates namespace information, and defeats CI/TDD gating where an agent wants *"all fast headless tests"* or *"all live adapter tests for `ShadowStudy`"*:

```text
# Ideal orthogonal selection:
Headless TDD loop (all modules):        TestCategory=Unit | TestCategory=Architecture
Single-feature headless loop:           FullyQualifiedName~Modules.ShadowStudy & TestCategory=Unit
Single-feature Revit adapter loop:      FullyQualifiedName~RevitAdapter.Modules.ShadowStudy
```

### 3.2 Critique & Refinement of the Proposed 5-Category Taxonomy

| Proposed Category | Host & Execution Profile | Speed / Concurrency | Critique & Recommended Seam Definition |
| :--- | :--- | :--- | :--- |
| **`Unit`** | `SyntheticTests.Logic` (`NUnit3TestAdapter`), zero `Revit.exe`. Uses pure POCOs, `Fake<Slice>Adapter`, `RevitAPIMock`/`RevitAPIUIMock`, and `[Apartment(ApartmentState.STA)]`. | **1–50 ms/test**; unlimited parallel workers. | **Keep.** Broaden explicitly to house pure logic, ViewModels, `RevitDOM` JSON/identity/diff algorithms, OpenXML `.xlsx` generation, property-based math checks, and **headless STA WPF View/Theme layout tests** (like [ThemeTests.cs](../../tests/SyntheticTests.Logic/Infrastructure/UI/ThemeTests.cs)). Do **not** split STA WPF tests into a 6th category; `[Apartment(ApartmentState.STA)]` manages threading transparently. |
| **`Architecture`** | `SyntheticTests.Logic` (`NUnit3TestAdapter`), zero `Revit.exe`. Reflection/IL graph inspection over compiled `Synthetic202X` + `SyntheticShared` assemblies (`NetArchTest.eNhancedEdition` or `ArchUnitNET`). | **~50–200 ms total**; runs on every fast TDD pass. | **Keep.** Enforces structural fitness rules that MSBuild cannot express while `SyntheticShared` shares one `.shproj`: e.g., ViewModels, `RevitDOM.Models`, and `Services/` classes behind `I<Slice>Adapter` must have zero dependency on `Autodesk.Revit.*`, `System.Windows.*` (for headless ViewModels), or `System.Windows.Forms`; all WPF Views declare explicit `SyntheticTheme` styles; no banned legacy patterns cross clean seams. |
| **`RevitSmoke`** | Live `Revit.exe` via `ricaun.RevitTest`. Verifies `Synthetic202X` assembly load, `App`/ribbon hydration, `ExternalEvent` dispatch, and real BAML `Window.Show()` with `_uiapp.MainWindowHandle`. | **~1–3 s total** (excl. boot); **must run non-parallel inside one `Revit.exe` UI thread** (`Nice3point` `RevitUiParallelLimit` lesson). | **Keep, narrow strictly.** Keep only 1–2 tests per add-in entry point / window / `ExternalEvent` seam (evolving [Tier2_RevitSmokeTests.cs](../../tests/SyntheticTests.Shared/Tier2_RevitSmokeTests.cs)). Heavy XAML layout/binding checks belong in `Unit` (`[Apartment(STA)]`), **not** `RevitSmoke`, to avoid inflating host UI-thread runs. |
| **`RevitAdapter`** | Live `Revit.exe` via `ricaun.RevitTest`. Verifies real `RevitAPI` adapters (`RevitShadowStudyAdapter`, `RevitIdentityService`, `StandardSerializationEngine`, `SettingsManager`, `FailurePipelines`) against an in-memory `NewProjectDocument` or a single rolled-back `TransactionGroup`. | **~50–500 ms/test**; sequential within one worker PID, zero shared disk mutation. | **Keep, enforce strict non-mutation contract.** Every test in `RevitAdapter` **must** leave `app.Documents` and disk state completely clean (`NewProjectDocument` closed via `doc.Close(false)` in `finally`, or `TransactionGroup.RollBack()`). Mirrors `Nice3point`'s `RevitApiTest` seam: exercises real C++ `RevitAPI` internals without touching external files or `EditFamily`. |
| **`RevitIsolatedDoc`** | Live `Revit.exe` via `ricaun.RevitTest`. Opens real fixture `.rvt`/`.rfa` templates, writes temp `.rvt` files (`SaveAs`), tests `EditFamily`/`LoadFamily`, linked-model transforms (`RevitLinkType.Create`), and detached workshared models. | **~1–10 s/test**; slow & stateful; sequential per worker PID with unique temp directories (`Guid`). | **Keep.** Directly parallels `DynamoDS`'s `[TestModel(...)]` fixtures. Because `EditFamily`, `LoadFamily`, `Schema` lookup registration, and `RevitLinkInstance` resolution mutate session-level Revit caches and hold OS file locks until `doc.Close(false)`, isolating them from `RevitAdapter` lets developers run fast adapter checks without waiting on heavy `.rvt` loads or multi-document temp cleanup. |

**Optional 6th Operational Tag — `Quarantine` (instead of `Dynamo`'s `"Failure"`):** If a test reproduces a confirmed upstream Autodesk Revit defect (for example, a broken rendering engine path in one specific Revit build) that cannot yet pass, mark it `[Category("Quarantine")]` coupled with `[Explicit("Known Autodesk Revit 202X issue #...")]` rather than commenting tests out. Because `ricaun.NUnit` (`1.5.0`) *does* natively honor `[Explicit]` and `[Ignore]`, `[Explicit]` reliably excludes quarantined tests from default `ricaun.RevitTest` runs!

### 3.3 Implementing `[Category]` Safely Given `ricaun.RevitTest` `1.11.1` Constraints

Because [SyntheticTests.Logic.csproj](../../tests/SyntheticTests.Logic/SyntheticTests.Logic.csproj) uses `NUnit3TestAdapter` (`4.5.0`) while `SyntheticTests2023–2026` use `ricaun.RevitTest.TestAdapter` (`1.11.1`), `Synthetic` must bridge two different runner realities:

1. **Define Typed Category Attributes** (following [NUnit CategoryAttribute Docs](https://docs.nunit.org/articles/nunit/writing-tests/attributes/category.html)) in a shared test helper file:
   ```csharp
   [AttributeUsage(AttributeTargets.Class | AttributeTargets.Method, AllowMultiple = false)]
   public sealed class UnitTestAttribute : CategoryAttribute { public UnitTestAttribute() : base("Unit") { } }

   [AttributeUsage(AttributeTargets.Class | AttributeTargets.Method, AllowMultiple = false)]
   public sealed class ArchitectureTestAttribute : CategoryAttribute { public ArchitectureTestAttribute() : base("Architecture") { } }

   [AttributeUsage(AttributeTargets.Class | AttributeTargets.Method, AllowMultiple = false)]
   public sealed class RevitSmokeTestAttribute : CategoryAttribute { public RevitSmokeTestAttribute() : base("RevitSmoke") { } }

   [AttributeUsage(AttributeTargets.Class | AttributeTargets.Method, AllowMultiple = false)]
   public sealed class RevitAdapterTestAttribute : CategoryAttribute { public RevitAdapterTestAttribute() : base("RevitAdapter") { } }

   [AttributeUsage(AttributeTargets.Class | AttributeTargets.Method, AllowMultiple = false)]
   public sealed class RevitIsolatedDocTestAttribute : CategoryAttribute { public RevitIsolatedDocTestAttribute() : base("RevitIsolatedDoc") { } }
   ```
   - This makes `--filter "TestCategory=Unit"` and `--filter "TestCategory=Architecture"` work immediately in `SyntheticTests.Logic`, and ensures Visual Studio Test Explorer / future TUnit or NUnit adapters recognize all five categories without magic-string typos.
2. **Pair Tier Categories with Deterministic Namespace / Naming Prefixes for `ricaun.RevitTest` `1.11.1`:**
   - Because `ricaun.RevitTest.TestAdapter` (`1.11.1`) only filters on `FullyQualifiedName` and `Name`, placing Revit-hosted tests into tier-prefixed namespaces or fixture names (e.g., `SyntheticTests.RevitSmoke.*`, `SyntheticTests.RevitAdapter.*`, `SyntheticTests.RevitIsolatedDoc.*`—evolving the existing `Tier2_` naming convention into `RevitSmoke_`, `RevitAdapter_`, `RevitIsolatedDoc_`) lets [test_executor.py](../../.agents/skills/revit-tests/scripts/test_executor.py) translate `--category RevitSmoke` cleanly into `--filter "FullyQualifiedName~RevitSmoke"` **today**, with zero dependency on an upstream `ricaun.RevitTest` adapter change.
   - Furthermore, [test_executor.py](../../.agents/skills/revit-tests/scripts/test_executor.py) can reflectively pre-filter test names via `CategoryAttribute` before invoking `ricaun.RevitTest.Console` (or pass explicit `FullyQualifiedName` matches), giving true `[Category]` CLI filtering even under `1.11.1`.

## 4. Evaluation of Candidate Additional Test Types

### (a) Golden-File / Snapshot / Round-Trip Contract Tests

- **Verdict:** **ADOPT — Fold into `Unit` (contract/snapshot verification) and `RevitAdapter` (live DB round-trip).** Do not create a separate top-level category.
- **Primary Precedent:** `specklesystems/speckle-sharp-connectors` uses `Verify` snapshot baselines to lock down complex serialized converter payloads; `Autodesk/revit-ifc` relies on minimal golden `.rvt`/`.ifc` round-trip files to catch silent parameter or mapping regressions across Revit releases.
- **Relevance to `Synthetic`:** `Synthetic` already created [PocoSnapshotExporter.cs](../../tests/SyntheticTests.Shared/Helpers/PocoSnapshotExporter.cs) and checked in [test_duplicate_families.json](../../tests/SyntheticTests.Shared/Assets/test_duplicate_families.json) and [test_duplicate_groups.json](../../tests/SyntheticTests.Shared/Assets/test_duplicate_groups.json). High-value contract targets include:
  1. **`RevitDOM` JSON schema & `IsTemplate` serialization (`Unit`):** Verify that committed `RevitDOM` JSON fixtures deserialize cleanly after model/property refactors (`ElementIdModel`, `ParameterModel`, `ViewModel`, `MaterialModel`) and round-trip deterministically (`POCO -> JSON -> POCO`) using `Verify.NUnit` or structural JSON equivalence.
  2. **Settings & Extensible Storage backward compatibility (`Unit` + `RevitAdapter`):** Golden-test [SyntheticSettings.template.json](../../src/SyntheticShared/SyntheticSettings.template.json) and legacy `DataStorage` JSON payloads (e.g., missing `ShadowStudy.SchemaVersion`, old `Settings` shapes handled by [SettingsManager.cs](../../src/SyntheticShared/Infrastructure/Persistence/SettingsManager.cs) and [LegacySettingsMigration.cs](../../src/SyntheticShared/Infrastructure/Persistence/LegacySettingsMigration.cs)).
  3. **`SheetIndex` OpenXML `.xlsx` output (`Unit`):** Because [SheetIndexExporterService.cs](../../src/SyntheticShared/Modules/SheetIndex/Services/SheetIndexExporterService.cs) writes pure OpenXML `ZipArchive` entries without Excel COM, golden/contract tests should extract `xl/worksheets/sheet1.xml` and `xl/styles.xml` from the generated `.xlsx` archive and assert XML structure, rotated header styles, merged ranges, and `"●"` **Issuance Indicator** placement—avoiding raw `.xlsx` binary byte comparison, which breaks on ZIP timestamps.
  4. **Live `RevitDOM` round-trip (`RevitAdapter`):** Extract from live `NewProjectDocument` -> JSON -> inject into fresh `NewProjectDocument` -> re-extract -> verify **Deep Diff Comparison** reports zero drift.

### (b) WPF Headless STA View / Theme / Layout Tests vs. In-Revit UI Smoke Tests

- **Verdict:** **ADOPT AS SPLIT-SEAM PRACTICE — Fold STA View/Theme/Layout tests into `Unit`; keep only thin `HwndSource` / `ExternalEvent` / BAML smoke checks in `RevitSmoke`.**
- **Primary Precedent:** `DynamoDS/Dynamo` isolates WPF UI tests (`DynamoCoreWpfTests`) from Revit execution; `Nice3point/RevitUnit` distinguishes serialized `RevitApiUiTest` (`UIApplication` thread) from standard tests; NUnit `[Apartment(ApartmentState.STA)]` supports full headless WPF instantiation without a running message loop.
- **Relevance to `Synthetic`:** [ThemeTests.cs](../../tests/SyntheticTests.Logic/Infrastructure/UI/ThemeTests.cs) already proves this pattern works locally: it boots a non-blocking WPF `Application` (`ShutdownMode.OnExplicitShutdown`) under `[Apartment(ApartmentState.STA)]`, loads `SyntheticTheme.xaml`, constructs `ShadowStudyWindow` with `FakeShadowStudyAdapter`, runs `Measure` / `Arrange` / `UpdateLayout`, checks button clipping bounds at compact heights, and raises `PreviewMouseWheelEvent`.
- **Implementation Guidance:**
  - Expand `ThemeTests`-style STA checks inside `Unit` across all WPF windows/UserControls (`ProjectStandardsDashboardWindow`, `MergeDuplicatesWindow`, `SyncSharedSitesView`, `MoveLinksView`, `ExportSheetIndexView`, `SettingsDashboardView`) plus a `PresentationTraceSources.DataBindingSource` listener that fails the test on any WPF binding error (`BindingExpression path error`).
  - Keep `RevitSmoke` minimal: verify real Revit-hosted BAML `pack://` URI resource loading inside `Synthetic202X.dll`, `HwndSource` ownership (`_uiapp.MainWindowHandle`), and `ExternalEvent.Raise()` execution.

### (c) Background Family-Document (`EditFamily` / `LoadFamily`) & Workshared / Linked-Model Tests

- **Verdict:** **FOLD INTO `RevitIsolatedDoc` — Do NOT create a separate category.**
- **Primary Precedent:** `DynamoDS/RevitTestFramework` groups model-loading tests via `[TestModel(...)]`; community best practices enforce `DetachFromCentralOption.DetachAndPreserveWorksets`, `try/finally` `famDoc.Close(false)`, and `WorksharingUtils.RelinquishOwnership` to prevent state leakage.
- **Relevance to `Synthetic`:** [RevitFamilyEnforcer.cs](../../src/SyntheticShared/RevitDOM/Operations/Standards/RevitFamilyEnforcer.cs) (`EditFamily` -> recursive nested family update -> `LoadFamily`), [Tier2_MergeDuplicatesIntegrationTests.cs](../../tests/SyntheticTests.Shared/Modules/MergeDuplicates/Tier2_MergeDuplicatesIntegrationTests.cs) (`DuplicateFamily`), and [Tier2_SharedCoordinatesIntegrationTests.cs](../../tests/SyntheticTests.Shared/Modules/SharedCoordinates/Tier2_SharedCoordinatesIntegrationTests.cs) (`SaveAs` temp unit model + `RevitLinkType.Create` + `RevitLinkInstance` transform verification) already exist in `SyntheticTests.Shared`.
- **Why No Separate Category:** From the test runner's standpoint, `EditFamily`/`LoadFamily`, linked `.rvt` loading, and detached workshared models share the exact same operational profile as any other `RevitIsolatedDoc` test: slow multi-document/temp-file I/O, session-wide cache mutation, and explicit `doc.Close(false)` cleanup in `finally` blocks. Creating separate `RevitFamily` or `RevitWorkshared` categories would fragment runner orchestration; feature-level filtering already works via `FullyQualifiedName~SharedCoordinates` or `FullyQualifiedName~RevitFamilyEnforcer`.

### (d) Failure-Handling / Warning-Injection Tests (`FailureMessage` / `IFailuresPreprocessor`)

- **Verdict:** **ADOPT DUAL-TIER COVERAGE — Fold pure rule evaluation into `Unit` and real transaction failure injection into `RevitAdapter`.**
- **Primary Precedent:** Autodesk `IFailuresPreprocessor` testing guidance emphasizes that `FailuresAccessor` and `FailureMessageAccessor` wrap native C++ Revit failure-manager objects with sealed constructors, requiring thin pure-C# rule seams for `Unit` tests **plus** live Revit `Transaction` tests that deliberately provoke warnings/errors to verify `FailuresAccessor.DeleteWarning` / `ResolveFailure` / rollback behavior.
- **Critique of `Synthetic`'s Current Gap:** [MockFailureFactory.cs](../../tests/SyntheticTests.Shared/Helpers/MockFailureFactory.cs) relies on `FormatterServices.GetUninitializedObject` against [MockRevitAPI.cs](../../tests/RevitAPIMock/MockRevitAPI.cs) and explicitly calls `Assert.Ignore(...)` whenever `REVIT2023–2026` is defined. As a result, `Synthetic` currently tests rule configuration in `Unit` (`TargetIdFailureRuleTests`, `SuppressConstraintsPresetTests`), **but has zero live verification that its `IFailuresPreprocessor` pipelines (`FailurePipelines.Purge()`, `DeleteWarnings()`, `CompositeFailuresPreprocessor`) actually suppress or resolve real Autodesk `BuiltInFailures` inside a Revit `Transaction.Commit()`**.
- **Implementation Guidance:**
  - Keep pure matching/composition logic in `Unit` (evolving `MockRevitAPI` or an `IFailureMessageAdapter` seam so `FormatterServices.GetUninitializedObject`—obsolete in .NET 8+—can be retired cleanly).
  - Add targeted `RevitAdapter` tests using a disposable `NewProjectDocument` that deliberately trigger deterministic Revit warnings/errors (e.g., identical overlapping walls or duplicate mark values, or failing constraint geometry) with `FailurePipelines` attached, asserting `TransactionStatus.Committed` vs `RolledBack` and zero modal warning dialogs.

### (e) Multi-Version `RevitAPI` / Preprocessor Compatibility & Journal Cleanliness Assertions

- **Verdict:** **ADOPT AS BUILD/HARNESS INVARIANTS — Do NOT create a `[Category("Journal")]` or `[Category("MultiVersion")]` NUnit category.**
- **Primary Precedent:** `Nice3point/RevitTemplates` and `speckle-sharp-connectors` verify multi-version compatibility by compiling and executing shared code/tests across target configurations (`net48`, `net8.0-windows`, `net10.0-windows`); enterprise Revit CI pipelines parse the session **Revit Journal** post-run for `DBG_WARN`, managed exception stacks, and uncommitted transactions.
- **Relevance to `Synthetic`:**
  1. **Multi-version `RevitAPI` & inverted `#if` hygiene:** Compiling and executing `SyntheticTests.Shared` across `SyntheticTests2023` (`net48`), `2024` (`net48`), `2025` (`net8.0-windows8.0`), `2026` (`net8.0-windows8.0`), and upcoming `2027` (`net10.0-windows`) directly tests runtime discrepancies. Complement this inside **`Architecture`** tests with a lightweight source/assembly check enforcing [revit-multi-versions SKILL.md](../../.agents/skills/revit-multi-versions/SKILL.md) rules (e.g., no stale unconditioned legacy `#if` defaults or obsolete `System.Drawing` / `IntegerValue` usage in unconditioned `#else` blocks).
  2. **Revit Journal cleanliness & leaked-handle invariants:** `Synthetic` already has [revit_journal_tool.py](../../.agents/skills/revit-journal-telemetry/scripts/revit_journal_tool.py) (per [ADR 0026](../../docs/adrs/0026-revit-journal-telemetry-strategy.md)). Rather than writing NUnit `[Test]`s that grep files mid-run, integrate `revit_journal_tool.py --assert-clean` into [test_executor.py](../../.agents/skills/revit-tests/scripts/test_executor.py) after `Revit.exe` worker runs to fail on unexpected `DBG_WARN`, unhandled `Synthetic.*` exceptions, or orphaned transactions—paired with an assembly-wide `[OneTimeTearDown]` invariant in `RevitAdapter` / `RevitIsolatedDoc` asserting `app.Documents.Size == initialDocCount` (catching leaked `NewProjectDocument` or `EditFamily` documents immediately at the fixture that leaked them).

### (f) Property-Based / Fuzz / Edge-Case Invariant Tests

- **Verdict:** **ADOPT SELECTIVELY — Fold into `Unit` using `CsCheck` (only for pure deterministic math, matching, and normalization engines).**
- **Primary Precedent:** `CsCheck` (native C#, PCG PRNG, deterministic seed replay, automatic numerical shrinking without F# runtime overhead) outperforms `FsCheck` for 3D transforms, affine matrix inverses, and IEEE-754 tolerances.
- **High-Leverage Targets in `Synthetic`:**
  1. **`SharedCoordinatesMath` (`Unit`):** Verify 3D transform composition, inverse round-trips ($T^{-1} \cdot T \approx I$), basis vector orthonormality, and elevation datum invariants across random coordinates, angles, and true-north rotations (catching gimbal/sign-flip bugs).
  2. **`SolarScheduleCalculator` & `ShadowImageCompositor` (`Unit`):** Verify altitude-threshold monotonicity, daylight timestamp bounds across arbitrary latitudes/longitudes/DST offsets, and Multiply-blend channel invariants (`[0, 255]` clamping, commutative frame ordering, darkness ceiling compliance).
  3. **`PocoIdentityService` & `StandardsDisambiguation` (`Unit`):** Fuzz arbitrary combinations of `UniqueId`, `Id`, `Class`, `Category`, `Name`, and `Aliases` to prove the 5-step fallback order and Type Guard never match across incompatible Revit classes or throw on null/whitespace/Unicode edge cases.
- **Constraint:** Do **not** apply randomized property-based testing inside live `RevitSmoke`/`RevitAdapter`/`RevitIsolatedDoc` suites; `Revit.exe` iteration cost and non-deterministic geometry tolerances make it unsuitable inside the host process.

### (g) UI Automation (`FlaUI` / `WinAppDriver`)

- **Verdict:** **SKIP.**
- **Primary Precedent & Desktop Evidence:** `FlaUI` (UIA2/UIA3) requires an active, unlocked, foreground interactive desktop session (`WinSta0\Default` with live focus), breaks in Session 0 or non-activating/off-screen worker windows, and suffers from WPF `Dispatcher`/animation race conditions and Revit host-frame focus contention.
- **Why Unnecessary for `Synthetic`:** As documented in [revit-test-sandboxing-feasibility.md](../../docs/research/2026-11-20-revit-test-sandboxing-feasibility.md), `Synthetic`'s parallel worker architecture deliberately suppresses `Revit.exe` foreground activation (`SW_SHOWMINNOACTIVE` / Virtual Desktop placement) to avoid stealing focus from the developer. Running UIA3 click automation would directly conflict with non-intrusive background test execution. `Synthetic`'s three-layer UI strategy—(1) ViewModel command/state logic in `Unit`, (2) STA `ThemeTests`-style `Measure`/`Arrange`/binding/event tests in `Unit`, and (3) `Window.Show()` + `ExternalEvent` checks in `RevitSmoke`—already validates the full UI seam deterministically at near-zero maintenance cost.
