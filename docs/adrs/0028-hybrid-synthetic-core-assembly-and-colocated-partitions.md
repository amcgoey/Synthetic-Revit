# ADR 0028 - Hybrid Synthetic.Core Assembly and Co-Located Partitions

Status: Accepted

## Context
Historically, `SyntheticShared` compiled pure **RevitDOM** models and engines, feature ViewModels/services, WPF views, and `Autodesk.Revit.*` adapters directly into each versioned `Synthetic<Year>` add-in assembly (`Synthetic2023`–`Synthetic2026`). Even after migrating from `.shproj` to SDK-style wildcard globs over `src/SyntheticShared/`, compiling everything into a single assembly per **Revit Version** created four architectural pressures:

1. **No Compiler-Enforced Purity Seam:** Pure logic could import `Autodesk.Revit.*` types or introduce `#if REVIT202*` preprocessor branches without any MSBuild error, silently coupling headless **RevitDOM** and domain logic to Revit or `RevitAPIMock`.
2. **Incomplete Multi-TFM Headless Verification:** Running `SyntheticTests.Logic` solely against `Synthetic2026` (`net8.0-windows8.0` with `RevitAPIMock`) left `.NET Framework 4.8` (`net48`, **Revit Versions** `2023–2024`) incompatibilities in shared pure C# unverified until live Revit builds.
3. **WPF BAML & Theme Resolution Fragility:** `Synthetic`'s `38` `.xaml` files—including `35` views and controls that previously merged [SyntheticTheme.xaml](../../src/Platform/UI/Addin/SyntheticTheme.xaml) via relative `Source` paths and now resolve it via [SyntheticThemeDictionary](../../src/Platform/UI/Addin/SyntheticThemeDictionary.cs)—rely on single-assembly BAML resolution inside `Synthetic<Year>` when loaded by [BootstrapApp.cs](../../src/Synthetic.Bootstrap/BootstrapApp.cs) into Revit's default CLR context (see [ADR 0018](0018-universal-add-in-bootstrap-manifest-routing-and-studio-deployment.md)).
4. **Migration & Locality Constraints:** Reorganizing roughly 360+ C# files across a single-shot rewrite is risky, whereas separating pure code and Revit adapters into distant top-level directory trees destroys vertical slice locality (as highlighted in [2026-11-21-revit-addin-test-categories-and-types.md](../research/2026-11-21-revit-addin-test-categories-and-types.md)).

## Decision
We adopt a **hybrid `Synthetic.Core` assembly** paired with **co-located slice partitions** (`Core/` + `Addin/` for production code; `Logic/` + `Revit/` for tests) driven by MSBuild wildcard globs and automated **Architecture Fitness Tests**:

1. **Multi-Targeted `Synthetic.Core` Assembly:**
   - [Synthetic.Core.csproj](../../src/Synthetic.Core/Synthetic.Core.csproj) (`<IsCoreProject>true</IsCoreProject>`, `<AssemblyName>Synthetic.Core</AssemblyName>`, `<RootNamespace>Synthetic</RootNamespace>`) multi-targets `net48;net8.0-windows8.0` (`Platforms=x64`, `PlatformTarget=x64`, `LangVersion=9.0`, `ImplicitUsings=disable`, `Nullable=enable`, `UseWPF=true`, `CopyLocalLockFileAssemblies=true`), explicitly referencing `System.IO.Compression` and `System.IO.Compression.FileSystem` on `net48`.
   - `Synthetic.Core` contains **zero** `Autodesk.Revit.*` references (`Revit_All_Main_Versions_API_x64` or `Autodesk.Revit.*` usings), **zero** `.xaml`/`.baml`/`.g.resources` artifacts, and **zero** `#if REVIT202*` preprocessor directives or constants.
   - [ArchitectureFitnessTests.cs](../../tests/Architecture/Logic/ArchitectureFitnessTests.cs) (`FitnessRule.CoLocatedPartitionLayout` and `FitnessRule.CorePurityAndZeroPreprocessor` across the 12-rule [`FitnessRule`](../../tests/Architecture/Logic/FitnessRule.cs) suite in [`ArchitectureFitnessRules.cs`](../../tests/Architecture/Logic/ArchitectureFitnessRules.cs), per [ADR 0029](0029-isomorphic-test-mirror-and-architecture-fitness-guardrails.md)) enforces these invariants at both source and compiled-assembly levels under [Synthetic.LogicTests.csproj](../../tests/Projects/Synthetic.LogicTests/Synthetic.LogicTests.csproj).
   - Both `Synthetic.Core` and `Synthetic2023`–`Synthetic2026` reference `Microsoft.Office.Interop.Excel` (`15.0.4795.1001`) with `<ExcludeAssets>runtime</ExcludeAssets>`, and the `EmbedExcelInteropTypes` target in [src/Directory.Build.targets](../../src/Directory.Build.targets) sets `<EmbedInteropTypes>true</EmbedInteropTypes>` on resolved `Reference`/`ReferencePath` items while stripping the PIA from `@(ReferenceCopyLocalPaths)` so `Microsoft.Office.Interop.Excel.dll` is never emitted to `Synthetic.Core` or `Payload/<Year>/` outputs.

2. **`Synthetic<Year>` Payload Assemblies & Single-Assembly XAML Hosting:**
   - [Synthetic2023.csproj](../../src/Synthetic2023/Synthetic2023.csproj)–[Synthetic2026.csproj](../../src/Synthetic2026/Synthetic2026.csproj) (`<IsRevitPayloadProject>true</IsRevitPayloadProject>`, `<RootNamespace>Synthetic</RootNamespace>`) reference `Synthetic.Core`, target each release's runtime (`net48` with `LangVersion=9.0` for `2023–2024`; `net8.0-windows8.0` for `2025–2026`), define `REVIT<Year>`, and compile Revit-coupled adapters, commands, and WPF views (following [revit-multi-versions SKILL.md](../../.agents/skills/revit-multi-versions/SKILL.md)).
   - `Synthetic<Year>` houses all `38` `.xaml` files—`35` themed views and user controls merging `<theme:SyntheticThemeDictionary />` ([SyntheticThemeDictionary.cs](../../src/Platform/UI/Addin/SyntheticThemeDictionary.cs), which resolves [SyntheticTheme.xaml](../../src/Platform/UI/Addin/SyntheticTheme.xaml) from the owning add-in assembly at `/{AssemblyName};component/Platform/UI/Addin/SyntheticTheme.xaml`), `2` un-themed views ([ExportSheetIndexWindow.xaml](../../src/Features/SheetIndex/Addin/Views/ExportSheetIndexWindow.xaml) and [CategorySelectionControl.xaml](../../src/Features/StandardsManagement/Addin/Views/CategorySelectionControl.xaml)), and `SyntheticTheme.xaml` itself—keeping all BAML and theme resource resolution inside the versioned payload DLL.

3. **Co-Located `Core/` + `Addin/` and `Logic/` + `Revit/` Slice Partitions & Clean Namespaces:**
   - Production source lives in the active 3-root vertical-slice layout under `src/Features/`, `src/RevitDOM/`, and `src/Platform/` (plus the thin loader under `src/Synthetic.Bootstrap/`). Every `.cs`/`.xaml` file under those three roots must reside under a `Core/` or `Addin/` subfolder, with `.xaml` permitted only in `Addin/`.
   - Tests follow the isomorphic mirror under `tests/Features/`, `tests/RevitDOM/`, `tests/Platform/`, and `tests/Architecture/` using `Logic/` and `Revit/` subfolders, with shared test helpers in `tests/Fixtures/Shared/` ([TestPathHelper.cs](../../tests/Fixtures/Shared/TestPathHelper.cs), [TypedCategoryAttributes.cs](../../tests/Fixtures/Shared/TypedCategoryAttributes.cs)) and `tests/Fixtures/Revit/`. Multi-TFM headless tests compile under [Synthetic.LogicTests.csproj](../../tests/Projects/Synthetic.LogicTests/Synthetic.LogicTests.csproj), live Revit integration tests compile under [Synthetic.RevitTests.2023](../../tests/Projects/Synthetic.RevitTests.2023/Synthetic.RevitTests.2023.csproj)–[Synthetic.RevitTests.2026](../../tests/Projects/Synthetic.RevitTests.2026/Synthetic.RevitTests.2026.csproj), and quarantined `RevitAPIMock` tests remain isolated in [Synthetic.LegacyMockTests.csproj](../../tests/Projects/Synthetic.LegacyMockTests/Synthetic.LegacyMockTests.csproj) (executed via [revit-tests SKILL.md](../../.agents/skills/revit-tests/SKILL.md)).
   - **Clean Namespaces:** Both `Synthetic.Core` and `Synthetic<Year>` share `<RootNamespace>Synthetic</RootNamespace>`, and C# namespaces reflect the slice domain while omitting `.Core`, `.Addin`, `.Logic`, and `.Revit` partition segments—for example, [RibbonItemFilter.cs](../../src/Platform/Host/Core/RibbonItemFilter.cs) (`Core/`), [App.cs](../../src/Platform/Host/Addin/App.cs) (`Addin/`), and [RibbonManager.cs](../../src/Platform/Host/Addin/RibbonManager.cs) (`Addin/`) all share `namespace Synthetic.Platform.Host`, and [RibbonItemFilterTests.cs](../../tests/Platform/Host/Logic/RibbonItemFilterTests.cs) uses `namespace SyntheticTests.Platform.Host`. Moving `App` and `RibbonManager` out of legacy `Synthetic.Core` into `Synthetic.Platform.Host` also prevents namespace/assembly name collisions with `Synthetic.Core.dll`.

4. **Distinct Cross-Assembly Static Class Names (`CS0433` Prevention):**
   - Because `Synthetic<Year>` references `Synthetic.Core` and both assemblies emit types into the same clean slice namespaces, duplicating a type name (especially on `static` helpers/managers) across `Core/` and `Addin/` triggers compiler error `CS0433` in downstream `Addin/` callers and test projects.
   - Co-located `Core/` and `Addin/` partitions must keep distinct cross-assembly type names reflecting each partition's responsibility—for example, pure JSON schema and visibility filtering live in `RibbonItemFilter` ([RibbonItemFilter.cs](../../src/Platform/Host/Core/RibbonItemFilter.cs)) while Revit ribbon API construction lives in `RibbonManager` ([RibbonManager.cs](../../src/Platform/Host/Addin/RibbonManager.cs)).

5. **MSBuild Globs, Pre-`Sdk.targets` Default-Item Opt-Out, Multi-TFM Output Separation, and SDK `<InternalsVisibleTo>`:**
   - **Wildcard Globs ([src/Directory.Build.targets](../../src/Directory.Build.targets)):**
     - `IsCoreProject == 'true'` includes `$(MSBuildThisFileDirectory)**\Core\**\*.cs` (excluding `Synthetic*\**`, `packages\**`, `obj\**`, `bin\**`) with `Link="%(RecursiveDir)%(Filename)%(Extension)"`.
     - `IsRevitPayloadProject == 'true'` includes `$(MSBuildThisFileDirectory)**\Addin\**\*.cs` and `<Page Include="**\Addin\**\*.xaml" />` (same exclusions), and stages flat runtime content from `src/Assets/` (`ribbon_config.json`, icons, `Templates/`), `Platform/Settings/Addin/Defaults/SyntheticSettings.template.json`, optional `SyntheticSettings.json`, and `Features/Worksets/Addin/Defaults/SyntheticWorksets.xlsx`.
   - **Pre-`Sdk.targets` Default-Item Suppression:** `Synthetic.Core.csproj`, `Synthetic2023`–`2026.csproj`, and `Synthetic.LogicTests.csproj` explicitly declare `<EnableDefaultCompileItems>false</EnableDefaultCompileItems>`, `<EnableDefaultPageItems>false</EnableDefaultPageItems>`, and `<EnableDefaultApplicationDefinition>false</EnableDefaultApplicationDefinition>` in their `.csproj` `<PropertyGroup>` rather than in `Directory.Build.targets`. Because MSBuild evaluates `Microsoft.NET.Sdk.targets` (which auto-populates default items) *before* importing `Directory.Build.targets`, setting these properties inside the `.csproj` ensures SDK default globbing is disabled before `Sdk.targets` runs.
   - **Multi-TFM Output Path Separation (`net48` vs `net8.0-windows8.0`):** [src/Directory.Build.props](../../src/Directory.Build.props) and [tests/Directory.Build.props](../../tests/Directory.Build.props) guard `<AppendTargetFrameworkToOutputPath Condition="'$(TargetFrameworks)' == ''">false</AppendTargetFrameworkToOutputPath>` and `<OutDir Condition="'$(TargetFrameworks)' == ''">$(OutputPath)</OutDir>`. Single-TFM projects retain flat output paths (`output/Synthetic/Payload/<Year>/`, `output/Synthetic/Bootstrap/v1/`, or isolated `bin/<Project>_<RunId>/`), whereas multi-TFM projects (`Synthetic.Core` and `Synthetic.LogicTests`) declare `<TargetFrameworks>net48;net8.0-windows8.0</TargetFrameworks>`, `<AppendTargetFrameworkToOutputPath>true</AppendTargetFrameworkToOutputPath>`, and `<OutDir></OutDir>` so `net48` and `net8.0-windows8.0` inner builds emit into separate TFM subfolders without overwriting one another. Post-build targets `SignDebugBuild` ([src/Directory.Build.targets](../../src/Directory.Build.targets)) and `WriteSyntheticProjectRoot` ([tests/Directory.Build.targets](../../tests/Directory.Build.targets)) guard on `'$(IsCrossTargetingBuild)' != 'true'` so they execute only on concrete inner builds.
   - **Test-Only SDK `<InternalsVisibleTo>`:** Replaces legacy `AssemblyInfo.cs` friend declarations with SDK `<InternalsVisibleTo>` items in [src/Directory.Build.targets](../../src/Directory.Build.targets): `IsCoreProject == 'true'` exposes `Synthetic.Core` to `Synthetic.LogicTests`, `Synthetic.LegacyMockTests`, and `Synthetic.RevitTests.2023`–`Synthetic.RevitTests.2026`, while `IsRevitPayloadProject == 'true'` exposes each `Synthetic<Year>` payload to `Synthetic.RevitTests.<Year>` (plus `Synthetic.LegacyMockTests` when `RevitVersion == '2026'`), keeping `Synthetic.Bootstrap*` unexposed.

## Alternatives Considered
1. **`.shproj` Shared Projects (`SyntheticShared.shproj`):** Rejected because compiling shared source directly into each `Synthetic<Year>` assembly cannot block `Autodesk.Revit.*` or `#if REVIT202*` leakage into pure logic, cannot run standalone multi-TFM (`net48;net8.0-windows8.0`) headless tests without `RevitAPIMock`, and loses SDK-style wildcard ergonomics.
2. **Per-Feature Core/Addin DLLs:** Rejected because splitting ~13 feature modules into separate `.csproj` assemblies multiplies project boilerplate, NuGet restore work, cross-module project references, and `Payload/<Year>/` runtime assembly surface for zero deployment gain when all features ship together in one Revit add-in.
3. **XAML-Splitting UI DLL (`Synthetic.UI.dll` or XAML inside `Synthetic.Core`):** Rejected because moving views out of `Synthetic<Year>` requires rewriting relative `SyntheticTheme.xaml` URIs across `38` `.xaml` files to assembly-qualified `pack://application:,,,/...;component/` URIs, increases BAML lookup fragility in Revit's shadow-copied context, and—if placed in `Synthetic.Core`—violates zero-BAML purity.
4. **Separate Top-Level Repo Roots (`src/Core/` vs `src/Addin/`):** Rejected because splitting pure logic and Revit adapters across distant root directory trees forces developers and agents to jump across parallel hierarchies for every feature change, eroding vertical slice locality.

## Consequences
* **Pros:** Enforces pure `Autodesk.Revit.*`-free, `.xaml`-free, `#if`-free multi-TFM (`net48;net8.0-windows8.0`) compilation for `Core/` code; enables zero-mock, zero-Revit unit and architecture testing across both TFMs via `Synthetic.LogicTests`; keeps feature logic, adapters, views, and tests co-located on disk across the active 3-root production layout (`Features/`, `RevitDOM/`, `Platform/`) and isomorphic `tests/` mirror; and resolves `SyntheticTheme.xaml` BAML safely inside each owning `Synthetic<Year>` assembly via `SyntheticThemeDictionary` without relative theme URIs or `Application.Current.Resources` pollution.
* **Cons:** Requires distinct cross-assembly class names (`CS0433` prevention) whenever `Core/` and `Addin/` types share a clean slice namespace; quarantines un-migrated `RevitAPIMock` tests in `Synthetic.LegacyMockTests` (coupled to `Synthetic2026`) until rewritten as pure `Logic/` or live `Revit/` tests; and ships `Synthetic.Core.dll` alongside `Synthetic<Year>.dll` in `Payload/<Year>/`.
