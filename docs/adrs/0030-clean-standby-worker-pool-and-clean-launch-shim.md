# ADR 0030 - Clean Standby Worker Pool, Clean-Launch Shim, and Startup Gate

Status: Accepted

## Context
Isolated cold **Revit Tests** ([ADR 0018](0018-universal-add-in-bootstrap-manifest-routing-and-studio-deployment.md)) allow concurrent builds and preserve open interactive Revit sessions, but four operational bottlenecks remain across Revit `2023–2027`:

1. **Cold-Boot Latency & Focus Disruption:** Every live test invocation boots a fresh `Revit.exe` (~25–45s cold OS cache; ~11–16s warm OS cache), spends ~3.5–15s initializing unrelated third-party add-ins (such as `CTC BIM Project Suite`, `Keynote Manager +`, and `Kinship`), and briefly steals desktop focus despite `/nosplash`.
2. **Third-Party Startup Concurrency Deadlocks:** Concurrent launches of the same **Revit Version** can collide inside third-party add-in `OnStartup` routines—verified in [2026-11-24-ctc-addon-concurrency-hang.md](../research/2026-11-24-ctc-addon-concurrency-hang.md), where seven `CTC BIM Project Suite` sub-tools perform an unguarded `File.SetAttributes`/`File.Delete` on shared `%PUBLIC%\CTC Software\CTC BIM Project Suite\<Tool> <Year> LastOnStartupLog.txt` files and deadlock Revit on `TaskDialog_External_Tools_External_Tool_Failure` until timeout.
3. **Absence of Native Per-Process Add-In Isolation:** Primary-source binary inspection across Revit 2023–2027 ([2026-11-24-clean-revit-test-addon-isolation.md](../research/2026-11-24-clean-revit-test-addon-isolation.md)) confirms Autodesk provides no per-process CLI switch, `Revit.ini` override, or `AddInsSettings.json` profile selector to disable third-party add-ins per launch while keeping **Add-In Bootstrap** and `ricaun.RevitTest.Application` enabled and preserving concurrent interactive Revit sessions.
4. **Standby & Sharded Journal Attribution ([ADR 0026](0026-revit-journal-telemetry-strategy.md) Extension):** Pre-booted **Standby Workers** start before any test run's `<RunId>` exists, and a sharded run produces multiple **Revit Journals** (one per consumed worker), so boot-time `SYNTHETIC_TEST_RUN:<RunId>` alone cannot deterministically attribute pre-test crashes or multi-shard runs.

## Decision
We adopt a standalone tooling subsystem (`tools/RevitWorkerPool` and `tools/RevitCleanShim`, decoupled from `src/Synthetic.sln` and studio Release deployment) implementing a hybrid **Worker Pool**, **Clean-Launch Shim**, and shared **Startup Gate**:

1. **On-Demand Standby Worker Pool With Single-Use Recycling & Bounded Lookahead:**
   - A local `.NET 8` **Worker Pool** supervisor manages pre-booted, single-use **Standby Workers** launched with `SYNTHETIC_TEST_WORKER=1` so **Add-In Bootstrap** bypasses payload loading while `ricaun.RevitTest.Application` listens on `\\.\pipe\ricaun.Revit.<PID>`.
   - Workers are never reused across test runs (avoiding CLR `AppDomain`/`AssemblyLoadContext.Default` stale-assembly caching): each consumed `WorkerPID` is terminated immediately after returning results and replaced asynchronously.
   - Lifecycle is on-demand: proactive `warm`, lazy auto-start on first run, explicit `drain`, Win32 Job Object `KILL_ON_JOB_CLOSE` containment, and a 20–30 minute idle scale-to-zero TTL.
   - **Concurrency & Lookahead Bounds:** Active executing workers are capped at `4` concurrent `Revit.exe` processes host-wide across all **Revit Versions**, with default auto-replenishment targeting `CURRENT_LATEST_VERSION` (`1` standby worker on lazy auto-start; `2` on proactive `warm`). Older versions execute on demand without persistent standby spares unless explicitly pre-warmed, except that sequential multi-version sweeps (`2023 -> 2024 -> 2025 -> 2026 -> 2027`) may pipeline `1` pre-warm of the next **Revit Version** within the `4`-worker cap as the current version enters its final shard. To eliminate wait under sustained multi-agent saturation without speculative idle waste, the supervisor may boot **at most `1` lookahead Standby Worker** (`TotalResident <= 5` temporarily) **only when all four guards hold**: (a) `ActiveWorkers == 4`, (b) queued work exists (`PendingShards + QueuedRuns > 0`), (c) **Clean-Launch Shim** is enabled (never in `--no-shim` mode), and (d) host available physical RAM (`GlobalMemoryStatusEx.ullAvailPhys`) is `>= 12 GiB`.
   - Worker readiness requires `ServerMessage.IsBusy == false` over the named pipe (never pipe existence alone, which succeeds before `DesktopMFCApp::doStartupWarnings` can deadlock on a modal dialog).
   - Zero-focus window suppression uses out-of-process `STARTUPINFO` (`SW_SHOWMINNOACTIVE`) plus `SetWinEventHook(EVENT_OBJECT_SHOW)` to place worker top-level HWNDs off-screen (`-32000, -32000` with `SWP_NOACTIVATE`), preserving WPF `window.Show()` / `IsVisible == true` without in-process Virtual Desktop COM coupling.

2. **Surgical User-Mode Clean-Launch Shim Behind `IWorkerProcessLauncher`:**
   - The **Worker Pool** isolates process creation behind an `IWorkerProcessLauncher` seam with two production adapters (`CleanDetoursProcessLauncher` default; zero-hook `StandardProcessLauncher` via `--no-shim` / `SYNTHETIC_CLEAN_SHIM=0`) plus an in-process test double (`StubWorkerProcessLauncher`).
   - `CleanDetoursProcessLauncher` spawns `Revit.exe` with a signed (`CN=Synthetic`) x64 user-mode Microsoft Detours hook DLL injected solely into `Revit.exe` (never propagated into `msedgewebview2.exe`, `AdskIdentityManager`, or other child processes).
   - To cover both `.NET Framework 4.8` (2023–2024) and `.NET 8/10` (2025–2027+), the shim filters directory enumeration (`FindFirstFile*` and `NtQueryDirectoryFile`/`NtQueryDirectoryFileEx`) and file open/attribute calls (`CreateFileW`/`NtCreateFile`/`NtOpenFile`/`GetFileAttributes*`) strictly on Revit's `.addin` roots (`%APPDATA%`, `%ProgramData%`, `%ProgramFiles%`) and `ApplicationPlugins` roots—exposing only Autodesk built-ins, `%APPDATA%\...\Synthetic<Year>.addin`, and `%APPDATA%\Autodesk\ApplicationPlugins\ricaun.RevitTest.Application.bundle` (while keeping `eTransmitForRevitDB.dll` readable on disk and hiding legacy `%ProgramData%\...\Synthetic*.addin`).
   - Reads and writes to `AddInsSettings.json` and `AdminSettings.json` are virtualized per worker PID into `%TEMP%\SyntheticCleanProfile\<PID>\`, preventing `APIInterop!updateAddInsSettings` write races against interactive Revit.
   - `CleanDetoursProcessLauncher` fails closed with a clear diagnostic error on injection or startup failure rather than silently degrading to an unshimmed Revit process.

3. **Shared Startup Gate & Modal Watchdog Safety Floor:**
   - Both zero-hook **Worker Pool** launches (`--no-shim`) and cold `test_executor.py --no-pool` runs coordinate via a shared per-version Win32 mutex (`Local\Synthetic_RevitStartupGate_<Year>`) held only across Revit's startup window until `doStartupWarnings` clears (leaving test execution parallel), paired with a worker-PID startup modal watchdog that detects `TaskDialog_External_Tools_External_Tool_Failure`, terminates only that PID tree, and retries once instead of waiting 660s.
   - Both pool and cold runs share the existing `Local\Synthetic_RicaunBundleLease` (`PackageContents.xml` shared-read without `FILE_SHARE_DELETE`) so concurrent runs never delete the test bundle mid-boot across Revit 2023–2027 without admin elevation.

4. **Cross-TFM ECMA-335 Metadata Discovery, Duration-Weighted Fair Sharding, & Journal Attribution Extension:**
   - The **Worker Pool** reads compiled test DLLs via BCL `System.Reflection.Metadata` (`PEReader`/`MetadataReader`) to expand `FullyQualifiedName` and typed NUnit `[Category]` filters across `net48`, `net8.0`, and `net10.0` without `Assembly.Load` TFM collisions.
   - When multiple `[TestFixture]` classes match and worker budget allows, the supervisor partitions work strictly at `[TestFixture]` boundaries (preserving per-fixture baseline caching under [ADR 0001](0001-hybrid-state-management-for-revit-tests.md)) into **Test Shards** using **duration-weighted Longest Processing Time (LPT)** scheduling backed by rolling per-fixture timings from merged `.trx` outputs (`%LOCALAPPDATA%\Synthetic\WorkerPool\fixture_timings_<Year>.json`, falling back to ECMA-335 test method count for unseen fixtures). Queued shards across concurrent agent runs dispatch in fair round-robin order one **Standby Worker** at a time and merge into a single `.trx` report.
   - **Extension of [ADR 0026](0026-revit-journal-telemetry-strategy.md):** Standby workers receive a boot-time `SYNTHETIC_WORKER_ID=<WorkerId>` environment variable that [BootstrapApp.cs](../../src/Synthetic.Bootstrap/BootstrapApp.cs) logs as `SYNTHETIC_WORKER_ID:<WorkerId>` in the **Revit Journal**. The **Worker Pool** returns every consumed `WorkerId` to [test_executor.py](../../.agents/skills/revit-tests/scripts/test_executor.py) (which builds via `.NET 10` `dotnet build`, prioritizes `net10.0` in `ricaun.RevitTest.TestAdapter` resolution, whitelists `Program Files` `ApplicationPlugins`, and gates machine-wide `2027+` `Program Files` manifests via preflight), which checks every shard's journal via `revit_journal_tool.py --worker-id <WorkerId> --assert-clean` (while preserving `SYNTHETIC_TEST_RUN:<RunId>` for cold `--no-pool` runs).
   - *(Note: `RevitWorkerPool`/`RevitCleanShim` remain `.NET 8` / `2023–2026`-scoped at Spec #216 close; post-close `.NET 10` / `2027` follow-ups—`RicaunBundleLease` `net10.0` priority, `Net10Probe`, live `2027` pool smoke coverage, `tools/build.ps1` SDK ordering, and `Ecma335TestDiscovery` `[Explicit]` handling—are tracked as coordination items on Spec #216.)*

## Considered Options
- **Unconditional Static Standby Overprovisioning (`+1–2` Always-Idle Workers Above `4`) & Subtractive Split (`3 Active + 1 Standby`):** Rejected because warm shimmed boots already finish in ~8–10s (smaller than the 26.5s method-count sharding skew fixed by duration-weighted LPT), static speculative boots waste CPU/`WebView2`/`win32k` headroom during active shards and idle unconsumed post-run, cause **Startup Gate** priority inversion in `--no-shim` mode, and reserving a standby inside cap `4` degrades 4-shard full suites by ~19–22s. Replaced by duration-weighted LPT, cross-version `N -> N+1` pipelining inside cap `4`, and the strictly demand-gated, shimmed-only, RAM-guarded `+1` lookahead.
- **Method-Count-Only Sharding:** Rejected as sole heuristic because fixture durations vary by >50x (for example `SharedCoordinatesRevitTests` vs. `AliasSwapEngineRevitTests`), producing >2x shard tail skew; retained solely as the unseen-fixture fallback.
- **Global File Mutations (Renaming `.addin` files, Swapping `AddInsSettings.json.bak`, `Revit.ini` `DisableUserAddinsAndMacros=1`):** Rejected because they break concurrent interactive Revit sessions, leave dirty state on crashes, lack Revit 2023–2024 support (`AddInsSettings.json`), or also disable `ricaun.RevitTest.Application` and **Add-In Bootstrap**.
- **Undocumented Revit Internals (`/localbasepath`, Journal Automation Playback, `EnableSlimStartupAddinFiltering`):** Rejected because `.NET` `Environment.GetFolderPath` bypasses `/localbasepath`, journal playback breaks in Revit 2027, and `addinsLoadInfo.ini` is machine-global in `%ProgramFiles%`.
- **Persistent Warm Daemon (`NUnit.Close=false`):** Rejected because CLR `AppDomain`/`AssemblyLoadContext.Default` cannot unload modified `Synthetic<Year>.dll` assemblies between code edits.
- **OS Virtualization & Secondary Accounts (`ProjFS`, Kernel Minifilter, MSIX/App-V, Sandboxie-Plus, Windows Sandbox, Containers, Secondary Local User, Single-Seat Hyper-V VMs, APS Design Automation):** Rejected due to system-wide virtualization roots, EV/WHQL driver signing, DirectX 11/`WebView2`/`AdskLicensingService` failures, single-seat concurrent-device licensing limits, or lack of `RevitAPIUI`/WPF support ([2026-11-20-revit-test-sandboxing-feasibility.md](../research/2026-11-20-revit-test-sandboxing-feasibility.md), [2026-11-24-clean-revit-test-addon-isolation.md](../research/2026-11-24-clean-revit-test-addon-isolation.md)).
- **Dedicated Clean CI Runner / VM With Extra Seat:** Valid zero-hook multi-seat option for future CI, but outside the `$0` single-workstation interactive+AFK constraint addressed here.

## Consequences
* **Pros:** Delivers ~1–3s warm test runs, eliminates third-party add-in boot overhead and CTC concurrency deadlocks, removes ~26s of full-suite tail skew via duration-weighted LPT sharding, pipelines multi-version sweeps inside cap `4`, absorbs multi-agent saturation via RAM-guarded `+1` lookahead without speculative idle waste, keeps interactive Revit untouched with zero host file mutation, and preserves deterministic `--assert-clean` journal gating across pooled and sharded runs.
* **Cons:** Introduces a standalone native C++ Detours DLL requiring MSVC x64 builds, local `CN=Synthetic` code signing, EDR/antivirus compatibility monitoring, and maintenance across future Windows/Revit `.NET` directory-enumeration changes (mitigated by the fail-closed `--no-shim` + **Startup Gate** and `--no-pool` fallbacks).
