## ADR 014 - Magic ID Intercept Pattern for Native API Singletons

Context: The Revit API uses stable negative IDs for certain built-in singleton elements (like -3000010 for the "Solid" line pattern or -1 for "" materials), but passing these IDs to doc.GetElement(id) returns null, causing standard resolution pipelines to fail. Decision: We implemented a "Magic ID" intercept pattern directly inside the ReferenceResolver that catches these specific IDs (or their string equivalents) and short-circuits the search, immediately returning the native API property (e.g., LinePatternElement.GetSolidPatternId()). Why: This completely abstracts the API's broken resolution behavior away from the translators, keeping the CategoryTranslator pure and boilerplate-free, while allowing our JSON payloads to maintain clean, human-readable labels like "Solid".
