# ADR 0025 - Non-Mutating Shadow Study Export, Headless Pipeline Seam, and Base-Ratio Multiply Compositing

Status: Accepted

## Context

Automating multi-view, multi-date **Shadow Study** frame exports and Multiply-blend **Shadow Composites** across Revit 2023+ (`net48` / C# 9.0 and `net8.0-windows8.0`) confronts several non-obvious platform, mathematical, and lifecycle constraints documented in [2026-11-19-revit-shadow-study-api.md](../research/2026-11-19-revit-shadow-study-api.md):

1. **Unexposed Cast Shadows Toggle (`REVIT-222419`) & Visual Style Constraints**: Revit 2023+ exposes no API property or writable parameter to toggle "Cast Shadows" or "Ambient Shadows" on a `View`, views assigned a `ViewTemplateId` reject direct mutations to `SunAndShadowSettings` and `ShadowIntensity`, `ViewDisplayBackground.CreateNone()` does not exist (`View.SetBackground` also throws on `ViewPlan`), `DisplayStyle.Wireframe` and `Rendering` never render cast shadows, and shaded styles (`Shading`, `ShadingWithEdges`, `FlatColors`, `Realistic`) vary directional lighting ($N \cdot L$) across hours even when `ShadowIntensity == 0`.
2. **Committed Regeneration vs. Undo Cleanliness & Settings Sync Drift**: `Document.ExportImage` ignores uncommitted `SunAndShadowSettings` mutations inside an open `Transaction`, yet committing per-frame transactions directly would permanently alter user views, trigger sibling-view template regenerations, and pollute Undo history. Conversely, saving machine-local UI preferences (`LastOutputFolder`, last pixel width/toggles) via `SettingsManager.Save` inside a rolled-back `TransactionGroup` leaves `SettingsManager._cache` split-brained, while committing them outside dirties the Undo stack on every Export and triggers `SettingsManager.CheckSyncDrift` false-positive toasts across workstations. Furthermore, legacy `SyncExternalEventHandler` Pull/Push code only serialized the original 4 settings modules, truncating newer modules from linked firmwide JSON.
3. **Project Timezone, `GetSunrise`/`GetSunset` DST Bug & UTC+ Midnight Wrap**: `StartDateAndTime` interprets `DateTimeKind.Local` against the workstation OS timezone rather than the Revit model's timezone, `SiteLocation.ConvertFromProjectTime` ignores `UsesDST`, `SunAndShadowSettings.GetSunrise`/`GetSunset` shifts UTC timestamps for DST year-round *"regardless of the value of the input date"* when `UsesDST == true`, and naive `SunriseUtc < frameUtc < SunsetUtc` comparisons fail in UTC+ timezones (`UTC+9`, `UTC+10`) where local afternoon sunset wraps past UTC midnight.
4. **Static Linework Self-Multiplication, Memory Spikes & WIC File Locks**: Naively multiplying $N$ full frames ($C_1 \times \dots \times C_N$) multiplies static non-shadow elements against themselves $N$ times—crushing sunlit halftone contours, gray hatches, and anti-aliased diagonal edges toward black—while default `ShadowIntensity = 50` saturates overlapping shadows within ~5 frames. Buffering $N$ decoded `3000 px` `Bgra32` frames at 15-minute summer cadence exceeds `1.3 GB` RAM, decoding without `BitmapCacheOption.OnLoad` locks temp files on Windows, and `WriteableBitmap` has STA thread affinity that breaks MTA NUnit runners.

## Decision

We structure `Features/ShadowStudy` (`Synthetic.Features.ShadowStudy`, partitioned into [`src/Features/ShadowStudy/Core/`](../../src/Features/ShadowStudy/Core/) and [`src/Features/ShadowStudy/Addin/`](../../src/Features/ShadowStudy/Addin/)) around three pure headless modules (`SolarScheduleCalculator`, `ShadowImageCompositor`, and `ShadowStudyPipeline`) above a single narrow Revit port (`IShadowStudyAdapter`), with **zero bundled `.rvt` template files**:

1. **Seam Discipline & Zero Revit/UI Leakage (`ShadowStudyPipeline` + `IShadowStudyAdapter`)**:
   - All DTOs, ViewModels, `ShadowStudyPipeline`, and `IShadowStudyAdapter` exchange pure `string` (`UniqueId` / serialized ID) identifiers and settings DTOs—never `Autodesk.Revit.DB.ElementId` or `Document`. Folder picking uses a dedicated `IFolderDialogService` (preserving existing `IFileDialogService` test doubles), and progress/cancellation crosses seams via injected `IProgress<ProgressState>` + `CancellationToken`.
   - `ShadowStudyPipeline` owns Category 1+2 orchestration headlessly: 0-frame date skipping, per-date `ShadowIntensity_N` lookup, invoking `IShadowStudyAdapter.ExportRawFrames`, running `ShadowImageCompositor`, writing `<OutputFolder>\<ViewLabel> - <DateLabel> - Composite.png` (with `<DateLabel>` formatted as `yyMMdd - <PresetName>` or `yyMMdd`, 24-hour `<HHmm>` frame names, and collision-only ` (<ViewType>)` suffixes when views share `View.Name`), and moving or cleaning up temp frame PNGs.
   - Modal `ShadowStudyWindow` closes (`DialogResult = true`) **before** `ProgressCoordinator.Initialize` opens modeless `SharedProgressWindow`, updating `ProgressCoordinator.UpdateStatus` / `UpdateProgress` / `IsCancelled` directly on the Revit UI thread and presenting the generalized `Platform/UI` [`ExportCompletionWindow`](../../src/Platform/UI/Addin/ExportCompletionWindow.xaml) afterward.

2. **Pure NOAA `[00:00..23:59]` Solar Schedule Evaluation**:
   - `IShadowStudyAdapter` extracts `SiteLocation` (`Latitude`, `Longitude` converted from radians to degrees, `TimeZone`, `PlaceName`) plus `UsesDST` (resolved from the active view's `SunAndShadowSettings`, falling back to the first eligible graphical view or `SunAndShadowSettings.GetActiveSunAndShadowSettings(doc)` when launched from a Sheet/Schedule) and **does not** call `GetSunrise`/`GetSunset`.
   - `SolarScheduleCalculator` generates clock-aligned project-local timestamps across `[00:00..23:59]` on each target date, converts explicitly to `DateTimeKind.Utc` via `effectiveOffsetHours = TimeZoneHours + (UsesDST ? 1.0 : 0.0)` (supporting fractional offsets such as `+5.5`), evaluates NOAA solar altitude directly, and retains timestamps where `SolarAltitudeDegrees >= MinSunAltitudeDegrees` (default `5.0°`, and strictly `> 0°` when threshold is `0°`), seamlessly handling UTC+ date wrapping, Polar Day, and Polar Night.

3. **Zero-`.rvt` View Preparation & Rolled-Back `TransactionGroup`**:
   - **Rejected Alternative (Bundled `.rvt` Shadow Templates)**: Although copying a pre-authored View Template from a bundled `.rvt` file can force `Cast Shadows = ON` despite `REVIT-222419`, shipping version-matched `.rvt` binaries across Revit 2023+ introduces manual authoring steps, installer bloat, `OpenDocumentFile` overhead, and annual Revit upgrade maintenance, whereas missing shadows are immediately obvious visually in the exported diagram. We therefore use a **zero-`.rvt`** approach: detaching `ViewTemplateId` inside the temporary group preserves the view's (or its assigned View Template's) existing Cast/Ambient Shadows state while unlocking `SunAndShadowSettings` and `ShadowIntensity`, with no external `.rvt` assets or pixel-warning heuristics.
   - **Deliberate Exception to `revit-transactions` `ExecuteCommittedBatchGroup` (`Assimilate()`):** While explicit **Save Preset** (`SettingsManager.Save`) and **Save Print Set** (`ViewSheetSetting`, preserving existing non-shadow `ViewSheet`/schedule/legend/drafting members on mixed sets and routing `InSession` sets through `SaveAs`) execute as intentional Undo-visible committed transactions, **Export** wraps all model/view mutations in [`DocumentTransactionExtensions.ExecuteRolledBackGroup(...)`](../../src/Platform/Revit/Addin/DocumentTransactionExtensions.cs), which unconditionally calls `RollBack()` in `finally` without masking inner exceptions, guaranteeing zero permanent model or Undo-stack mutation. Machine-local UI preferences (`LastOutputFolder`, last pixel width, toggles) persist in `%APPDATA%\Synthetic\ShadowStudyUserPrefs.json`, while `ShadowStudySettings` (`SchemaVersion = 1`, defaults initialized in parameterless constructor and deep-cloned on edit) stores shared **Shadow Study Presets** and studio defaults—updating `SettingsManager`, `Config`, `SyntheticSettings.template.json`, `SettingsDashboardViewModel`/`Window.xaml`, and unifying `SyncExternalEventHandler` across all registered settings modules (tolerating absent keys on legacy projects in `CheckSyncDrift`).
   - All inner transactions execute via `DocumentTransactionExtensions.ExecuteTransaction(...)` with `FailurePipelines.ObserveOnly()` (never blanket `FailurePipelines.DeleteAllWarningsRecorded()` or raw `DeleteAllWarnings()`) and roll back explicitly (`tx.RollBack()`) on inner exceptions before `ExecuteRolledBackGroup` rolls back the outer group, while a `DialogBoxShowing` scope suppresses `TaskDialog_Really_Print_Or_Export_Temp_View_Modes`.
   - Eligible views (`FloorPlan`, `CeilingPlan`, `AreaPlan`, `EngineeringPlan`, `ThreeD` excluding `Walkthrough`, `Section`, `Elevation`, `Detail`) keep their Crop Box and Scope Box strictly untouched (surfacing a non-blocking UI warning badge when `CropBoxActive == false`). Inside the setup `Transaction`, the adapter detaches `ViewTemplateId` (`ElementId.InvalidElementId`, retaining all template-inherited graphics including its shadow state without regenerating sibling views), sets `SharesSettings = false`, `SunAndShadowSettings.Visible = false`, `SunAndShadowType.StillImage`, and `SunriseToSunset = false`. By default (or automatically when a view is `Wireframe`/`Rendering`, accompanied by a UI warning badge), it sets `DisplayStyle.HLR` (guarded by `CanModifyDisplayStyle()`) and `ViewDisplayBackground.CreateGradient(white, white, white)` (guarded strictly to 3D, Section, and Elevation views) and exports one `ShadowIntensity = 0` reference pass. When preserving non-`HLR` shaded styles, it exports a `ShadowIntensity = 0` reference pass per timestamp to match hourly $N \cdot L$ shading before exporting the `ShadowIntensity_N` frame via `ExportRange.SetOfViews` (`HLRandWFViewsFileType = PNG`, `ShadowViewsFileType = PNG`, `ZoomFitType.FitToPage`, `FitDirectionType.Horizontal`, `PixelSize`).

4. **Streaming, MTA-Safe Base-Ratio Multiply Compositing**:
   - For $N \ge 1$ frames and target minimum brightness $B_{\min} = 1 - (\text{MaxCompositeDarknessPercent} / 100.0)$ (clamped to `[1..95%]`, default `80%` $\implies B_{\min} = 0.20$, `RGB ~51`), per-date intensity is $\text{ShadowIntensity}_N = \max(1, \min(100, (int)\text{Math.Round}(100.0 \cdot (1.0 - \text{Math.Pow}(B_{\min}, 1.0 / N)))))$ (written without `Math.Clamp` for `net48` / C# 9.0 compatibility).
   - `ShadowImageCompositor` streams PNGs sequentially via `FileStream` (`FileAccess.Read`, `FileShare.Read`) and `PngBitmapDecoder` with `BitmapCacheOption.OnLoad` (closing streams immediately so temp files never lock), normalizes to straight-alpha `PixelFormats.Bgra32`, validates identical `PixelWidth × PixelHeight`, accumulates per-channel ratios $\min(1.0, C_{i,c} / B_{i,c})$ into a single `double[]` buffer, writes final `Bgra32` bytes with `Alpha = 255`, and encodes via `BitmapSource.Create` + `Freeze()` + `PngBitmapEncoder`.

## Consequences

- Zero binary `.rvt` template files need to be authored, packaged, opened during export, or re-saved for future Revit releases; users keep control of Cast/Ambient Shadows on their views or View Templates while `ViewTemplateId` detachment unlocks per-frame sun and shadow intensity adjustments cleanly.
- Multi-view **Print Set** batches keep **Export** 100% non-mutating, Undo-clean, and free of false firmwide sync-drift alerts, and unifying `SyncExternalEventHandler` over `SettingsModuleRegistry` prevents firmwide settings truncation.
- Halftone contours, hatches, anti-aliased diagonal edges, optional shaded colors, and `#000000` linework remain crisp and memory-bounded across any frame cadence, timezone (`UTC-12..UTC+14`), or hemisphere, with 100% headless **Logic Tests** coverage (`Synthetic.LogicTests`, [`tests/Features/ShadowStudy/Logic/`](../../tests/Features/ShadowStudy/Logic/)).
